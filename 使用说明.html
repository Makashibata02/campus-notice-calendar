从配置到第一条提醒

本说明对应当前程序的实际功能。先配置 DeepSeek，再配置发信邮箱，最后导入通知、检查候选并确认入历。

首次使用API Key邮箱字段各邮箱开启方法通知文件类型识别与课表提醒与备份故障排查

1. 第一次使用，按这六步进行

  1. 运行安装包，按向导完成安装，打开“校园通知日历助手”。无需另外安装 Python 或 Node。
  2. 点击左侧“设置”。填写 DeepSeek 模型名称、API Key；再填写 SMTP 主机、端口、发件邮箱、收件邮箱和授权码。
  3. 分别点击模型区域的“保存模型设置”和邮箱区域的“保存邮箱设置”。输入后必须保存，测试按钮读取的是已保存配置；运行开关通过“保存运行设置”另行保存。
  4. 点击“测试模型连接”，检查 API 连接；再点击“发送测试邮件”，确认提示并检查收件箱、垃圾邮件和订阅/通知分类。
  5. 点击“添加通知”，选择“文字”并保存一小段通知。在“导入与审核 → 材料”选中材料，点击“识别此材料”；完成后进入“待审核”，点击一行查看侧边详情，检查日期、时刻、地点、行动要求及提醒。
  6. 点击“确认入历”，或勾选多项后“确认所选”。回到日历检查结果。只保存材料或只完成识别，都不会自动建立正式提醒。
API Key 用于向 DeepSeek 请求识别；邮箱授权码用于通过你的邮箱发信。它们是两种不同的凭据，不能互相填写。你也可以先不配服务，使用“新建事项”手动管理日程。

2. DeepSeek API Key：获取、填写与测试

2.1 到哪里获取

  1. 打开 DeepSeek 开放平台并登录或注册。
  2. 进入平台的 “API Keys / API 密钥”页面，可尝试直接打开 API Keys 管理页。
  3. 点击“创建 API Key”或同义按钮，名称可填写“校园通知日历助手”，按平台当前提示创建。
  4. 复制完整密钥，直接填入本应用。不要把示例占位文字、两端引号、前缀 Bearer 、首尾空格或换行一起复制进去。不要用 DeepSeek 账号登录密码替代它。
  5. 在平台检查 API 可用额度与账户状态。创建密钥本身不代表已有可用调用余额；具体计费、充值与赠送额度以平台显示为准。

官方依据：DeepSeek 首次调用说明。这里只使用官方开放平台签发的 Key，不需要运行文档中的代码。

2.3 常见 API 问题

提示先检查什么
未配置 Key / 401是否已保存；是否完整复制；是否误填登录密码、其他平台 Key，或密钥已撤销。必要时在官方平台创建新 Key，再保存。

超时 / 500 / 503本机网络或服务端状态。等待当前任务结束再重试；失败材料会保留，不需要马上重复上传。

3. 邮箱配置：先分清发件箱与收件箱

发件邮箱 A负责向外发送，需要开启 SMTP 并生成授权码；收件邮箱 B只负责收到提醒，不需要在本应用填写它的密码或开启它的 SMTP。A 与 B 可以相同，也可以不同，测试时用两个 QQ 邮箱更容易分辨。

设置字段含义与示例
SMTP 主机发件邮箱服务商的发信服务器。例如 A 是 QQ 邮箱，就填 smtp.qq.com，不要加 https://。
端口按下面对应邮箱表格填写。它是数字，例如 465。
使用隐式 TLS465：通常勾选，连接建立时就加密；587：不勾选，本应用会要求 STARTTLS 升级加密。“不勾选”不表示允许明文发信。
发件邮箱A 的完整邮箱地址，包含 @qq.com 等后缀。它同时用于登录 SMTP 和发件人地址。
收件邮箱B 的完整邮箱地址。本版本填写一个收件地址，不要输入多个地址或姓名。
邮箱授权码A 为第三方客户端生成的专用密码；Gmail 对应“应用专用密码”。不要填 B 的密码，也不要默认使用 A 的网页登录密码。

QQ 邮箱 A → QQ 邮箱 B 的完整填写例子

SMTP主机：smtp.qq.com 端口：465 使用隐式TLS：勾选 发件邮箱：邮箱A的完整地址 收件邮箱：邮箱B的完整地址 邮箱授权码：邮箱A生成的授权码

按“保存邮箱设置 → 发送测试邮件 → 确认发送 → 在 B 中查收”的顺序操作。看到“邮件服务已接收”表示服务端已接受邮件；真正进入收件箱仍要在 B 中确认。测试邮件不需要先上传通知或调用大模型。

4. 常见邮箱怎样开启 SMTP

以下以个人免费邮箱为主。服务商可能调整界面名称；优先查找“第三方服务”“客户端”“POP/IMAP/SMTP”“授权码”等词。只有 QQ 已在本项目完成真实收信测试，其他邮箱按公开文档提供配置方法，仍需用自己的账号测试。

发件邮箱SMTP 主机端口本应用隐式TLS认证凭据
QQ（@qq.com）smtp.qq.com465勾选QQ 邮箱授权码
网易163（@163.com）smtp.163.com465勾选客户端授权密码
网易126（@126.com）smtp.126.com465勾选客户端授权密码
Gmail（@gmail.com）smtp.gmail.com465勾选符合条件账号的应用专用密码
新浪（@sina.com）smtp.sina.com587不勾选，使用STARTTLS新浪邮箱授权码

参数参考：腾讯官方邮件连接配置（QQ）；厂商公开 SMTP 兼容参数（网易、新浪）；Google SMTP 文档（Gmail）。只参考对应服务的主机和端口；本应用保留证书验证，不采用其他设备文档中的“禁用可信证书”设置。

4.1 QQ 邮箱：新版网页入口

  1. 在电脑浏览器登录 QQ 邮箱，确认当前登录的是发件邮箱 A。
  2. 点击右上角头像，进入“设置 → 账号与安全 → 安全设置”。
  3. 在第三方协议服务处点击“开启服务”，开启 POP3/IMAP/SMTP 相关服务。
  4. 开启后点击“生成授权码”，按页面指引使用 QQ 密码或手机 QQ 扫码等方式验证身份。具体方式由账号当前页面决定。
  5. 获得16位授权码，可备注“校园通知日历助手”。回到本应用，填写 A 的完整地址及该授权码，再填写 B 的地址。
  6. 使用表中 smtp.qq.com / 465 / 勾选隐式TLS，保存邮箱设置后发送测试邮件。

旧界面可能位于“设置 → 账户 → POP3/IMAP/SMTP”，应以当前界面为准。更改 QQ 账号密码可能使原授权码失效；撤销可到“账号与安全 → 设备管理 → 授权码管理”。

来源：QQ 官方授权码获取及管理说明。

4.2 网易 163 邮箱

  1. 登录 163 邮箱网页版。
  2. 点击上方“设置 → POP3/SMTP/IMAP”，有些版本显示为“POP/SMTP/IMAP”。
  3. 开启含 SMTP 的服务，例如“IMAP/SMTP服务”。如页面提示保存，完成保存。
  4. 点击“新增授权密码”，按提示完成身份验证，复制生成的客户端授权密码。它通常只显示一次。
  5. 在应用填完整的 @163.com 发件地址、该授权密码，服务器用 smtp.163.com、端口 465、勾选隐式TLS。
  6. 保存邮箱设置，再发送测试邮件。邮箱服务中“已开启”不等于应用中“已保存”。

4.3 网易 126 邮箱

  1. 登录 126 邮箱网页版，进入“设置 → POP3/SMTP/IMAP”。
  2. 开启含 SMTP 的服务，并通过“新增授权密码”完成验证，生成该 126 账号自己的授权密码。
  3. 本应用填写完整 @126.com 地址，主机改为 smtp.126.com，端口 465，勾选隐式TLS；不要沿用 163 的主机。
  4. 保存邮箱设置，测试发信并在收件箱确认。

163/126 也可通过网易邮箱大师手机端：“我 → 邮箱管理 → 选择账号 → 第三方登录管理 → 通用授权码 → 新增授权码”。遗失授权码时新增一个，再更新应用设置。

来源：网易官方新增授权码说明。

4.4 Gmail：先开启两步验证，再生成应用专用密码

  1. 登录发件 Gmail 对应的 Google 账号安全设置。
  2. 开启“两步验证”，完成 Google 提示的设置。
  3. 打开 应用专用密码，按提示重新验证身份，为“校园通知日历助手”创建密码。
  4. 将生成的16位应用专用密码填入本应用“邮箱授权码”，复制时不要加入展示用分隔空格。不要填写日常 Google 登录密码。
  5. 主机填 smtp.gmail.com，端口 465，勾选隐式TLS；发件地址填写完整 Gmail 地址，保存并测试。

若没有应用专用密码入口，可能与组织账号政策、高级保护计划或两步验证方式有关；不要反复尝试普通密码。Google 优先推荐 OAuth 登录，但本应用尚未接入该方式，因此这里只适用于允许应用专用密码的账号。本机还需要能够连接 Google 邮件服务。更改 Google 密码后，可能需要重新生成应用专用密码。

来源：Google 应用专用密码说明、Google SMTP 参数。

4.5 新浪邮箱（@sina.com）

  1. 登录 新浪邮箱网页版，进入“设置 → 客户端 POP/IMAP/SMTP”；部分页面需先进入“更多设置”。
  2. 开启授权码状态，按页面要求完成手机验证，取得16位授权码。
  3. 同时确认 POP/IMAP/SMTP 服务状态已开启。只生成授权码而未启用服务，仍可能无法登录。
  4. 本应用发件地址填写完整 @sina.com 地址，主机 smtp.sina.com，端口 587，不勾选隐式TLS，由应用要求 STARTTLS 加密。
  5. 填写该账号授权码，保存后测试。重置授权码后应同步更新本应用。

来源：新浪官方授权码及服务开启说明；服务器参数见上方厂商参数表。其他新浪域名或企业版请按对应账号官方配置，不直接套用。

4.6 Outlook / Hotmail、学校邮箱与企业邮箱

Outlook.com / Hotmail 暂不作为本版本的发件邮箱教程。微软要求 Modern Auth / OAuth2，而当前应用只有“SMTP用户名＋授权码”方式，尚未接入微软 OAuth 登录。仅填写 smtp-mail.outlook.com:587 或换普通密码不能解决认证方式不匹配。它们仍可作为收件邮箱。

依据：微软官方 Outlook.com 参数和认证要求。

学校或单位自有域名邮箱，请向管理员获取 SMTP 主机、加密端口、认证方式以及是否允许第三方客户端。不能仅凭学校网页地址推断服务器，也不能把 QQ 或网易个人邮箱参数直接用于企业邮箱。如果组织要求 OAuth、专用客户端或其他登录策略，本版本可能不适用。

5. 可以提供哪些通知和文件

适合课程通知、组会安排、学术讲座、报名截止、作业提交、课程大纲中的阶段安排，以及含周次/节次的课表。你需要主动提供材料。可以粘贴公开网页链接，应用会读取该页正文与图片；不会自动接入微信群、QQ群或邮箱。

输入类型支持的格式 / 方式大小及处理限制怎样准备更清楚
公众号 / 公开网页 / H5 / 图片网页粘贴完整的 https:// 或 http:// 链接，点击“读取链接”正文最多10万字符，页面图像最多10屏；超限会提示拆分先检查正文及图片预览，再点击识别。验证码、登录或访问限制页面需打开原文，自行补充正文或截图。
直接粘贴文字“添加通知 → 文字”正文框每次最多10万字符保留通知标题、年份、日期、时间和上下文；先点“保存文字”，再识别。
文本通知.txt文件不超过10 MB；识别文字仍须不超过10万字符建议 UTF-8 编码。出现乱码时，用记事本另存为 UTF-8，或直接复制正文。
聊天截图 / 海报 / 通知照片.png .jpg .jpeg .webp；可选择、拖入文件或粘贴剪贴板图片单张不超过10 MB。超长截图会分段；内容太长或请求过大需再手工拆开。字迹清晰，保留原消息日期；尽量去掉大段无关聊天，避免缩成难读小字。
文字型 PDF.pdf，默认按页提取文字单文件不超过50 MB；提取后的文字最多10万字符适合可选中、复制文字的课程大纲、日程表或通知。
扫描 PDF / 复杂表格 PDF仍是 .pdf，选页转成图像后识别单文件不超过50 MB；每次转图最多10页在“PDF转图页码”输入 1,3,5，使用文件从第一页开始的页码，不是印刷页脚编号。

文件选择或拖入每批最多10个。多文件导入后逐份选择并点击“识别此材料”，不会自动识别全部文件。长截图单次识别最多接受30个图像片段，请求内容约45 MB上限；超限提示后拆成更短截图。

暂不直接支持的类型

Word（.doc/.docx）、Excel、PPT、HEIC、GIF、ZIP、音频/视频、邮件文件（.eml/.msg）、ICS 日历均不能直接作为文件导入。Word/PPT 可导出 PDF；表格可导出需要的页面为 PDF 或截图；HEIC 可转换为 JPEG/PNG；邮件可复制正文或截图；网页使用链接入口，读取失败时再补充正文或截图。转换时应保留清晰度和日期上下文，不能只修改扩展名。

粘贴公众号、H5或图片文章链接

  1. 点击“添加通知”，选择“链接”，在链接框中填入完整网址，点击“读取链接”。读取网页与识别日程是两步，读取后不会直接写进日历。
  2. 在“材料”列表选中本次材料，侧边详情会保留原网址和正文。展开“查看网页图片与页面截图”，检查图文通知是否读全。图片文章和H5中可加载的内容会通过页面渲染截图交给模型；页面图像最多10屏，超长内容需手动拆分。
  3. 检查材料后，点击“识别此材料”，再逐项审核候选。图片上的文字可能漏识别，重要时间和行动要求仍须对照原文。
  4. 公众号提示“环境异常”、验证码或需要登录时，点击“打开原文”在浏览器自行查看，再点击“补充正文或截图”。补充材料会保留原网址，方便回看；程序不会绕过验证。
  5. 点击“重新读取”会沿用原网页材料的上传序号。手工补充的正文或截图另存为新材料，按新的上传顺序参与审核。
本版只读取文章内容，不识别报名二维码、不进入报名小程序，也不自动报名。H5只读取可正常加载的页面内容；登录后页面、多步骤交互、音视频和需要点击翻页才能出现的内容可能需要手工截图补充。网页读取可能使用已配置的DeepSeek Key，费用以其 网页读取服务说明 为准。

PDF 与相对日期的具体操作

  1. 导入 PDF 后，在“材料”列表选中它，查看侧边详情中的文字预览。文字缺失、表格顺序混乱时，在转图页码框填写需要的页码，例如 2,3，再点击“识别此材料”。
  2. 页码框留空表示按文字提取。处理下一份文字型 PDF 时记得清空上次填写的页码；不要把 1-10 当作页码列表，应逐项填写 1,2,3...。
  3. 通知写“明天下午三点”时，填写原消息实际发送日期，不是今天的上传日期。例如原消息日期为2027-11-01，“明天”才对应2027-11-02。
  4. 没有可信基准、只有“下周”“稍后通知”等表述时，保留待确认状态，在审核页补充后再入历。只有日期时可选择“仅日期”，不要自行补造具体时刻。

这里的支持范围来自本项目当前导入与解析实现，不等同于 DeepSeek 平台或其他软件所支持的全部格式。

6. 从候选到日历、重复课表

6.1 列表与侧边详情

  1. “导入与审核”包含“待审核”与“材料”两个视图。新增入口统一为“添加通知”，弹窗提供链接、文字、文件三种方式；导入后先查看材料，识别后再审核。
  2. “待审核”默认显示全部候选，可按来源、事项类型及需要补充信息筛选，并搜索标题。新一次识别完成后会定位到该材料的候选。
  3. 点击候选行打开侧边详情，在“事项”中检查名称、类型、课程/项目、日期、时间、地点、行动要求及提醒；在“原通知”中核对该候选的正文、图片或链接。勾选复选框只用于批量选择，不会确认入历。
  4. 切换候选、切换页面或处理其他候选，会保留本次会话中未保存的编辑；退出软件前请保存需要保留的修改。识别结果可能遗漏要求，请对照原材料。
  5. 一份通知含活动与报名截止时，分别核对两项。相对日期没有可信基准、时间含糊或仍缺必要信息的内容，应补充后再确认；重复课程先设置课表规则。

6.2 批量确认与删除

  1. 勾选候选后，列表顶部显示已选数量，可点击“确认所选”或“删除所选”。“全选当前结果”只勾选当前筛选结果；改变筛选或离开审核页会清空选择，避免误处理隐藏内容。
  2. 批量确认前会检查所选条目。存在缺日期、需要补充时间、重复课程等问题时，整批不会入历；按提示逐项处理后再确认，不会偷偷跳过问题项。
  3. 多余或不需要的候选，可单条删除，也可勾选后“删除所选”。批量删除只确认一次，会显示数量和部分标题。原材料、已入历事项和提醒不会跟着删除。
  4. 如果所选候选已被确认或移除，本次整批不删；查看刷新后的列表，重新确认选择。缺日期等不完整候选仍可删除。之后主动重新识别原材料时，仍可能生成相同候选。

6.3 更新已有事项

  1. 同一事项改期时，在详情的“写入方式”选择正确的已有事项，再预览更新。同名但不同日期的组会默认独立，不能仅因名称相同就选错更新目标。
  2. 确认后才进入日历。同事项冲突字段按上传顺序采用新值，后上传未提及的字段沿用；旧材料迟到确认不会覆盖较新字段。重复内容不会另增日程或重新发送相同提醒。
  3. 日历顶部可以切换周、月与列表，搜索或筛选课程/项目。点击日程打开详情侧栏，查看来源、修改、完成或取消；近期安排栏可以收起。

6.4 重复课程

  1. 在“学期与课表”打开“学期与节次”，填写学期名、第一教学周的周一、总周数和真实节次作息表，保存学期。
  2. 新增课程系列，在侧边详情填写星期（周一为1，周日为7）、起止节次、开始/结束周、每周/单双周；若填明确周次 1,3,7，以明确周次为准。
  3. 点击“预览日期”，核对每次日期和总次数，再保存系列。同一门课每周两个时段分别建系列。
  4. 某一次停课/调课：在日历详情修改“本次”。整体改教室/规则：回课表页修改整个系列，已单独调整或取消的场次默认保留。
  5. 修改节次表后，重新预览并保存受影响的系列。学校调休、补课不自动推断，需手动处理。

7. 提醒、后台运行与备份

默认活动/课程提前30分钟，精确截止任务提前1天；仅日期事项当天09:00提醒。以审核页选择的提醒为准。后台每30秒检查一次，因此不是精确到秒的闹钟。

在“提醒记录”中按状态筛选，点击一条记录查看详情、错误说明和可用的重试操作。结果不确定时，先检查收件箱，再决定是否重试。

建议的手工定时测试

  1. 先确保“发送测试邮件”已能收到。
  2. 新建“定时提醒测试”，设为当前时间往后11分钟开始，提醒选择提前10分钟，保存。
  3. 约1—1.5分钟后检查收件箱及“提醒记录”。不需要等到活动开始。
  4. 可以关闭主窗口测试托盘运行，但不要从托盘退出，也不要关机或休眠。
提醒状态含义
待发送未到时间，或等待必要的发信配置；不等于发送失败。
邮件服务已接收SMTP服务接受了邮件，仍需在收件箱或垃圾邮件中确认。
失败检查授权码、服务状态或网络。认证错误不会持续自动重试。
投递结果不确定网络中断等情况可能发生在服务接收之后，先查收件箱再决定是否手动重试。
已错过 / 已取消事项已过期，或已被修改、取消、完成、删除；不按旧安排继续发送。

关闭窗口后收起到右下角托盘；托盘可打开、暂停/恢复提醒或退出。登录 Windows 自动启动默认关闭，可在设置开启。完全退出、关机和休眠期间不能发信；恢复时，仅补发尚未开始/截止的事项，不集中补发过期邮件。

设置页的“备份与恢复”区域可导出备份。备份包含日历、原材料和版本信息，不含 API Key 和邮箱授权码；恢复前自动备份当前数据，恢复后提醒暂停，检查无误再开启。换电脑需重新填写凭据。本版本保存凭据时优先使用 Windows 加密；界面保存后会清空密码框，显示“已配置”，再次保存时留空会保留原凭据。

8. 遇到问题，按顺序检查

现象处理方法
填完仍提示未配置 / 测试使用旧值先在对应区域点击“保存模型设置”或“保存邮箱设置”，再测试；不要只填输入框就点击测试。
EAUTH / 邮箱认证失败检查发件地址是否完整、授权码是否来自同一个发件账号、SMTP是否开启、授权码是否已失效。重新生成后保存。不要把收件箱密码填进来。
连接失败 / ECONNECTION / EDNS / 超时检查主机拼写、网络及对应端口是否可达，核对465与TLS勾选配对。Gmail还取决于本机能否连接其服务；学校网络可能限制SMTP。
邮件未收到，但状态是待发送看计划提醒时间是否已到；确认事项已入历、提醒未关闭、全局提醒未暂停、电脑及程序仍在运行。到时后允许最多约30秒扫描。
状态为服务已接收，收件箱仍没有核对已保存的收件地址，查垃圾邮件、订阅/通知分类及服务商延迟。不要立即连续重发。
网页读取失败 / 环境异常 / 需要验证检查链接是否完整；点“打开原文”自行查看，随后用“补充正文或截图”添加所需内容。不要把验证页当作活动通知。可重试读取，不能保证所有公众号文章均可自动访问。
网页超过10屏 / 页面内容未完整加载复制所需通知段落，或分段截图后导入。检查图片预览，特别是懒加载长图、交互H5和分页内容。
图片识别不完整提高截图清晰度、拆开超长图、保留时间上下文；可先粘贴文字定位。导入成功不保证识别准确。
PDF没有文字 / 页码错误检查是否为扫描件，填写1起算的明确页码列表，最多10页；加密PDF先自行解锁并导出可读副本。
事项入历失败补充具体日期与必要时间，确认结束晚于开始；重复课程转到课表规则设置，避免凭空猜测学期周次。

配置指南按2026-10-31可见文档编写。服务商界面、账号策略和模型能力可能变化；不确定时以相应官方帮助和账号页面为准。无需向聊天发送你的 Key 或授权码。
